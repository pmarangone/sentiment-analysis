# Project Domain Context

This repository manages a distributed system composed of a `backend`, `consumer` services, and `dashboards`.

## Glossary

| Term | Definition |
| :--- | :--- |
| **Backend** | The central service responsible for core business logic and state management. |
| **Consumer** | Services that process events or data streams originating from the backend. |
| **Dashboard** | Visualization components for system metrics and operational monitoring. |

## Modeling Philosophy

This `CONTEXT.md` serves as the authoritative glossary for the project. 

The domain modeling skill distinguishes between:
1. **Reading**: Merely using `CONTEXT.md` to look up terminology or understand existing definitions. This is a passive act.
2. **Sharpening**: The active discipline of challenging terms, inventing scenarios to probe edge cases, refining fuzzy language, and updating the glossary immediately when new clarity is achieved. 

Sharpening turns the model from a static document into a living design tool that continuously evolves with our understanding of the system.
